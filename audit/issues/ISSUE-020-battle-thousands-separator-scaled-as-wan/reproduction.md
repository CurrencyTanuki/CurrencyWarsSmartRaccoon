# ISSUE-020 修前复现：战斗裸千分位被结算规则放大一万倍

## 真实数据事实

2026-08-09 的真实节点归档中，战斗伤害面板包含：

- 节点 1-1：第一名 `3.7万`，第二名原文 `3,545`；
- 节点 1-2：第一名 `6.4万`，第二名原文从 `7,089` 增长到 `8,863`。

当前战斗路径复用 `ParseSettlementDamageCandidates`。结算页规则会在单位不可见时把带分隔符数字推断为“万”，因此：

- `3,545` 被解释为 `35,450,000`；
- `8,863` 被解释为 `88,630,000`。

这两个结果分别比同一排行榜第一名大约 958 倍和 1,385 倍，却仍位于第二名，违反伤害排行顺序；按战斗基础数值解释为 `3,545` 和 `8,863` 才与画面顺序和既往节点量级一致。

上述两数只是当前已保存帧的行值，不代表最终节点总伤害；本项不得把 `40,545` 或 `72,863` 宣称为最终节点值。

## 稳定修前红灯

新增纯语义测试，分别把 `3,545`、`8,863` 送入战斗专用解析入口，要求：

1. 值保持基础单位 `3,545` / `8,863`；
2. 规范千分位形式可以作为战斗行的明确基础数量表达；
3. 结算页 `1,234 → 12,340,000` 的既有合同保持不变。

修前生产代码没有战斗专用解析入口；若临时以当前实际调用的结算解析器执行，结果稳定为放大一万倍。
