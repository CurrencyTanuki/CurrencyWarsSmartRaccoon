# 来源与质量规范

## 来源记录

每个公开来源单独生成一个 evidence 文件，至少记录：标题、平台、作者、URL、发布日期（无法确认则 `unknown`）、访问日期、内容类型、适用版本和版权/复用状态。

视频中的玩法结论必须给出对应时间点，不能只给视频总链接。无法获得精确时间点时，结论保持 `unverified`，写入粗粒度窗口和 `unknowns`，不得进入 verified playbook。

## 事实、建议与推断

- 官方或页面直接可核对的机制：`source_fact`。
- 作者的阵容、运营、装备或转型建议：`author_recommendation`。
- AI 跨来源归纳：`ai_inference`，并降低置信度。

来源作者的强度评价不是官方事实。伤害、连胜、0T、最强等展示值不能外推为普遍结果。

## 冲突

冲突双方都要保留；用 `conflicts` 互相引用并标记 unresolved、resolved 或 not_comparable。只有新证据能解决冲突，不能因“更像正确”而删除其中一方。

创作体验服、正式服、热修前后或不同难度的资料优先视为适用范围差异，而不是强行合并。

## 去重

同 URL、同视频 ID 或明确转载链可共享 `deduplicationKey`。去重只合并重复发布，不删除独立作者、独立实测或不同日期的来源。

## 版权和隐私

- 默认 `linked_only`；只保存短转述、定位和必要事实。
- 不捆绑无授权正文、字幕、图片、视频或付费内容。
- 不保存账号、Cookie、令牌、UID、私人文件路径或个人联系方式。
- 不运行来源提供的可执行文件、脚本或浏览器扩展。

## 高风险建议

信息不足、冲突或低于 playbook 最低置信度时，不得自动执行刷新、出售、购买、换阵等不可逆操作。使用 `missingInformationPolicy` 明确降级到提示、人工复核或安全备选。
