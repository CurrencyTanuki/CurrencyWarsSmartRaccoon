# 输入隔离方案决策

## 不可变安全边界

不读写游戏内存，不注入 DLL，不 Hook 游戏，不修改游戏文件、驱动、反作弊或网络流量。任何要求突破这些边界的方案不进入实验。

## 方案对比

| 方案 | 独立指针/焦点 | 对当前游戏与识别的兼容性 | 改码 | 性能/直播 | 风险与恢复 | 结论 |
|---|---|---|---|---|---|---|
| 再插一只物理鼠标 | 否；Windows 桌面仍只有一个系统指针 | 当前 `SendInput` 与用户鼠标互相覆盖，游戏仍需前台 | 无 | 无额外负载 | 低风险但无效 | 排除 |
| 单机前台分时 | 否 | 完全兼容当前稳定路径 | 无 | 性能最好 | 自动化时不能自由开发；按 `Ctrl+Shift+F12` 可回退 | 立即可用的临时方案 |
| 定向 HWND 消息（如 `PostMessage`） | 理论上不移动系统指针；不等于拥有第二个真实指针 | 游戏可能使用 Raw Input/DirectInput 或忽略失焦消息；必须实机黑盒验证 | 中 | 低负载，适合直播 | 平台/反作弊风险未知；必须默认关闭并保留原后端 | 研究型候选，不可承诺成功 |
| Windows 虚拟桌面 | 否 | 只是窗口组织，不隔离会话输入 | 无 | 无帮助 | 恢复容易 | 排除 |
| 快速用户切换/RDP | 会话可隔离，但普通 Windows 本地控制台只有一个活动终端；切换可能中断游戏渲染/捕获 | 游戏、GPU 和反作弊兼容性差 | 中 | 直播捕获复杂 | 断连/黑屏/会话切换风险 | 不推荐 |
| 虚拟机 | 是，客体有独立输入 | GPU 加速、游戏反作弊、窗口捕获均需验证，性能和稳定性不确定 | 高 | 同机争抢 GPU/内存；OBS 捕获路径更复杂 | 快照可恢复，但游戏账号风险和部署成本高 | 不作为首选 |
| 第三方多席位/设备隔离驱动 | 可能真正隔离 | 驱动层与反作弊兼容性未知 | 低到中 | 可能稳定，也可能引入显示/输入异常 | 系统驱动、付费、卸载残留风险高 | 不安装、不推荐 |
| 第二台电脑运行游戏与自动化；当前电脑直播和开发 | 是，物理隔离 | 当前程序基本无需修改；截图和点击留在游戏机 | 低；可选局域网状态接口 | 负载和故障域分离，最稳定 | 硬件/采集成本；任一台可独立回退 | 长期首选 |

## 为什么两只鼠标不够

Windows Raw Input 能识别事件来自哪一只 HID 鼠标，但默认桌面仍将传统鼠标输入合成为同一个系统指针。当前程序没有读取某只实体鼠标，而是直接把绝对移动和点击写入系统输入流；用户移动任意物理鼠标都会与它竞争位置。把 Raw Input 加到助手中只能知道“是谁动了鼠标”，不能让游戏和 IDE自动拥有两个桌面焦点。

## 推荐实施路径

### A. 现在：单机分时直播

1. 游戏以无边框窗口运行，自动化期间保持前台。
2. OBS 使用游戏捕获，不捕获整个桌面。
3. 弹幕和直播管理放到手机；开发只在一轮自动化停止后进行。
4. 所有切出游戏前先按 `Ctrl+Shift+F12`，确认日志出现 `EmergencyStopRequested`。
5. 失败时切到“故障/暂停”场景，再人工处理。

这是最低成本、最少代码风险的可用方案，但不满足“边刷边自由开发”。

### B. 单机后台输入实验

只有用户决定继续后才实施，且必须遵守：

- 在现有 `IInputController` 后增加独立实验实现，原 `Win32InputController` 不改行为。
- 配置默认为 `ForegroundSendInput`；实验后端必须显式启用，程序启动时醒目提示。
- 只使用公开 Windows 窗口消息/自动化 API，不访问游戏进程内部。
- 每个动作仍使用现有“截图识别 → 输入前检查 → 一次输入 → 后置截图验证”；API 返回成功不能作为成交成功。
- 若游戏失焦、不再渲染、坐标路径不同、消息被忽略或出现遮罩，立即失败并回退，禁止无限重试。
- 逐项验收点击、按键、拖拽、刷新、购买、退出结算；任何一项不可靠都不能宣称支持后台模式。
- 完整回归现有前台模式，不允许后台实验降低安全停止能力。

验收条件：连续至少 100 个受控动作不移动系统指针；用户同时在 IDE 中移动鼠标和输入文本时，游戏动作正确、IDE 不收到游戏输入；截图与后置验证无新增误判；紧急停止在 500 ms 内取消后续输入；游戏更新和分辨率变化后重新验收。

### C. 长期：双机

游戏机运行游戏和助手，工作机运行 OBS、IDE、弹幕和录播。优先使用采集卡获得最稳定的视频；无采集卡时可先用局域网 NDI/低延迟串流验证，但网络串流会与 B 站上行共享带宽。助手未来只需通过局域网发送脱敏状态和日志，不发送账号凭据。

## 恢复策略

- 前台模式异常：`Ctrl+Shift+F12` → 确认停止日志 → 手动接管。
- 实验后台模式异常：关闭实验开关 → 重启助手 → 使用原 `ForegroundSendInput`。
- VM/驱动方案未获确认前不安装，因此不存在系统级回滚任务。
- 双机采集异常：OBS 切换到暂停场景；游戏机继续本地运行或安全停止，二者互不影响。
