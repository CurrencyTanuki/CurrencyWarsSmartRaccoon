### 0.4 识别管线（备战页，核心）

`Phase2OperationalScreenshotAnalyzer.AnalyzeAsync`（Tasks 项目）：
1. **页面分类** → 确认备战页（preparation_*）
2. **并行读取**：节点号、难度、金币/利息/累计花费、商店 Lv、血量、人口、
   装备工具数、羁绊、阵容（前台4格 + 后台动态格 + 备战席）、库存
3. **阵容识别**：OpenCvCharacterCardRecognizer（模板匹配 85+ 角色模板，
   Normalize 到 1920×1080 → 槽位裁剪 → Shortlist/Rank/Match）
4. **星级**：分区算法（前台双带列投影 / 后台+备战席原始帧星核连通域）
5. **装备**：Phase2IconRecognizer（SHA256 分组模板匹配，47 组共享图标）
6. **羁绊**：实机面板 OCR 或阵容推算累加（合并补 NextThreshold）
7. **输出**：Phase2OperationalState（Observation<T> 每字段带置信度/证据）

## 三、本轮关键根因（教训）

1. **"识别到了"≠"识别对"**——测试断言必须对照 ground truth（已建立）。
2. **数字黑字问题**：商店 Lv 是深蓝底**黑色**数字（max≈69），OCR 与 BrightOnDark
   模板都提取不到——需要反相+对比度拉伸预处理。
3. **模板裁剪必须与识别槽位一致**：佩佩模板首版偏左 65px → 匹配负相关。
4. **人口不能依赖等级字段**：等级 OCR 失败（progress Unknown）时人口一起丢。
5. **应援路径破坏 SlotIndex**：单槽识别返回 index=0。
6. **星级星带漂移**：固定带漏卡底星、动态带误判装饰——双带折中。
7. **sliding 高度档**：去掉 16/20 小档后 "7" 不再识别（16/20 对局部匹配有用）——
   恢复 10 档。
