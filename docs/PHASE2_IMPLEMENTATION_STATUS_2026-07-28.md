## 已实现并接入当前程序

### 攻略合同与建议引擎

- `1.0.0` 版本化攻略 JSON Schema、严格解析和版本检查。
- 游戏状态、观测状态、证据、置信度、事件、局势分析和建议模型。
- 支持自动选路、锁定攻略、锁定流派三种选择方式。
- 条件支持阶段、阵容、羁绊、商店、经济、环境、策略、装备、特殊物品、专家顾问等字段；未知信息按攻略指定策略拒绝、跳过或要求复核。
- 建议输出保留规则来源、定位说明、收益、代价、风险和失效条件，不把来源中的经验性结论伪装成官方规则。
- 已提供一套能够完整加载并参与判断的 4.4 攻略数据。

### 单张截图分析

- 从现有程序选择一张 16:9 截图，或直接捕获当前游戏窗口。
- 复用第一阶段的页面分类、角色卡模板、金币识别、OCR、商店读取和开局页面读取能力。
- 当前已实现的页面专用提取：
  - 备战 `preparation_1_1` / `preparation_1_2`：前台、后台、阵容、羁绊和经济。
  - 奖励商店 `reward_shop`：商店角色及与商店页面相符的状态。
  - 节点成功 `challenge_success`：队伍生命值和本节点总伤害；伤害小数单位支持“万/亿”，零伤害行使用 OCR 与像素结构组合确认。
  - 节点失败 `challenge_failed`：队伍生命值；没有伤害证据时保持未知。
  - 敌人概览 `enemy_overview`：已有 OCR 可读取的敌人与阶段信息。
  - 投资环境选择页 `investment_environment`：已有 OCR 可读取的候选环境。
- 不支持的页面和无法可靠读取的字段会返回 `Unknown`，并显示证据、置信度和不确定项，不生成伪造值。
- 通过现有归一化坐标和识别器兼容 16:9；真实回归覆盖 1920×1080 与 2048×1152，页面匹配的既有回归还覆盖 1280×720、1600×900、2560×1440 和 3840×2160。

### 只读实时收集器

- 每 2 秒读取游戏窗口，不发送鼠标或键盘输入，因此不改变第一阶段自动化流程。
- 页面或结构化状态发生变化时保存截图、分析 JSON 和 JSONL 事件；状态不变时去重，每分钟保留一次检查点。
- 原始截图、识别证据、置信度、缺失字段和冲突状态均保留，可供后续重新处理。
- 连续失败最多 5 次后明确停止，不会无限循环。
- 事件归并器按发生时间和观测时间处理新值、重复事件、冲突和陈旧数据。

### 现有界面集成

- 当前主窗口新增“局势分析与数据收集”入口。
- 分析窗口提供选择截图、分析当前游戏、启动/停止只读收集，以及状态、攻略建议、证据、警告和原始 JSON 展示。
- 第一阶段主窗口、配置、自动重刷入口和两个游戏内悬浮窗没有被替换。
