# ISSUE-007 根因：商店 compact 装备裁剪纵向几何错误

## 已排除的方向

- 不是普通/特权重复图标组内无法区分：本项只要求保留共享视觉组
  `066/105`，仍应为 `Unknown / null EquipmentId`。
- 不是名称或本地 ID 互换：`066/105` 与 `080/119` 是两组不同 PNG
  哈希；原截图中可见图标与 `066/105` 的显示器/矩阵造型一致。
- 不是匹配器、置信度或候选排序错误：同一匹配器只要收到正确裁剪，
  `066/105` 就会成为最高分组。
- 不是 ISSUE-005 的决策语义，也不是 ISSUE-006 的相邻槽边缘污染。

## 原生商店连续帧约束下的二维网格

为避免只按单图恢复 `0.82`，又对问题图与 `video_prep/prep_0..5.png`
六张原生 1920×1080 reward-shop 连续帧扫描：

- `Y=0.80..0.90H`（步长 0.01）；
- `Height=0.20..0.30H`（步长 0.02）；
- 问题图必须把 `066/105` 排第一；
- 六帧的 4×3 个装备子槽必须维持目视确认且跨帧稳定的前景真值：
  `TTT / FTF / FTF / FTF`。

结果：

|---:|---:|---|---:|---:|
| 0.83 | 0.26 | `066/105` | **0.851910** | **0** |
| 0.83 | 0.24 | `066/105` | 0.808120 | 0 |
| 0.84 | 0.26 | `066/105` | 0.804469 | 0 |
| 0.83 | 0.28 | `066/105` | 0.783898 | 0 |

图标主体，故是当前真实素材约束下的最小、可追溯几何修正。

## 最小修改边界

只把 reward-shop compact Front 的装备子槽从
`Y=0.90H / Height=0.30H` 改为 `Y=0.83H / Height=0.26H`。
不修改 X、宽度、标准 Preparation、Back、inventory、模板、匹配算法、
置信度、候选映射、前景门槛或保存决策语义。
