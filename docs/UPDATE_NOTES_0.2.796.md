# 0.2.796 更新说明（2026-08-03）

## 修复用户实测反馈的两个问题

### 问题 1：节点被识别成 1-9（备战页 1-3 显示"最近 1-9"）
**为什么之前每次修都不好（根因终于查透）**：
1. 页面模板只有 `preparation_1_1`（锚点 preparation_stage_1_1）和
   `preparation_1_2`（锚点 preparation_stage_1_2）——**1-3 及以后没有模板/锚点**；
2. 实机 1-3 备战页分类器只能匹配 `preparation_generic`（"备战阶段"通用标签），
   置信度被 Clamp 在 0.55~0.80；
3. `preparation_generic` 不含节点号 → 节点解析只能靠 OCR 小区域
   （PreparationNodeValue）→ 实机分辨率下 OCR 把 "1-3" 读成 "1-9"；
4. 之前所有修复（页面 ID 优先、正则改范围）都没解决"分类器拿不到节点"这一层。

**本次修复**：`ReadNodeAsync` 增加**备战页节点兜底**——小区域数字 OCR
全部失败时，用含"备战阶段"前缀的**大区域全文 OCR**解析"备战阶段 1-3"
完整格式（带上下文 OCR 更稳，且校验完整格式）。这样即使分类器只认出
`preparation_generic`，节点号也从"备战阶段 1-3"文本中正确提取。

### 问题 2：0.05s 盲点连点根本没执行
**为什么**：你双击桌面"启动货币战争智能狸.vbs"启动的其实是 **0.2.780**
（计划任务 CWTLaunchApp 仍指向 0.2.780 旧版）——旧版没有盲点连点逻辑，
且测试日志证实 12:16 会话跑的是旧版（"启用快速点击路径"是旧文案）。

**本次处理**：
1. 桌面 vbs 已改为**直接启动 0.2.796**（不再走指向旧版的计划任务）；
2. 盲点连点触发条件修正：**只要标准博弈就启用**（不再要求先选"快速版"），
   与你的方案一致（"如果用户选择的是标准博弈选项，这些延时全部去掉"）；
3. 盲点连点间隔 0.05s → **0.1s**（4 秒连点 40 次 / 3 秒连点 30 次）。
