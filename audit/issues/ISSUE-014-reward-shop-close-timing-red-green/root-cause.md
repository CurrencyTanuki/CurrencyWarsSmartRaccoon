# ISSUE-014 根因分析

状态：历史失败根因未能在当前版本重现；不作猜测性修复。

## 已确认事实

- `CloseShopAsync` 先用 `ReadStablePageAsync` 要求连续两帧稳定页面；确认 `reward_shop` 后只发送一次测试点击，测试替身立即切换为准备页。
- `WaitForPageAsync` 在五秒墙钟期限内要求连续两帧 `preparation_generic`，轮询间隔 350 ms。
- 历史失败耗时约 28–31 秒，接近三次关闭尝试各自五秒验证、并叠加真实 OpenCV 页面分类在高负载下的耗时。
- 同一源码和测试素材曾在隔离进程 1.984 秒通过，此后多轮全量也持续通过。

## 当前判定

- 60 次当前运行全部通过，包含 8、16、24 个进程的受控并发；当前没有可验收的修前红灯，也没有证据支持修改生产逻辑。
- 并发组测试耗时从隔离时约 1.88 秒上升到最高 8.47 秒，证明真实 OpenCV 分类对 CPU 争用敏感。
- `WaitForPageAsync` 只在轮询顶部检查 deadline；一次分类可以跨过五秒界限后仍完成当前观察。因此“测试总耗时超过五秒”本身不等于验证超时，也不能据此反推稳定缺陷。
- 历史三次约 28–31 秒失败与全量运行负载相关是合理候选解释，但当时没有保存逐轮分类耗时或事件流，当前不能把该推断写成已确认根因。

## 保留边界

- 真实游戏捕获、真实点击、动画过渡和焦点切换是否能稳定关闭商店。
- 在未来全量或实机再次出现失败时，必须保存页面分类逐次耗时、分类结果、事件流和系统负载，重新打开本问题。

因此本项不改超时、不减少连续帧确认、不增加重试、不改页面分类阈值，也不通过禁用并行或放宽断言掩盖潜在问题。
