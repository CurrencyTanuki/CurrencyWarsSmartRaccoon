# ISSUE-018 根因与修改边界

## 根因

这是两个紧密相连的输入安全契约缺口：

1. 自动刷开局启动时会显示 `OperationPanelWindow`，但不会覆盖持久化的
   `IsLogOverlayClickThrough=false`。因此用户或另一版本留下的共享设置可以让本程序自己的
   置顶面板遮住游戏操作点。
2. `Win32InputController.ClickWithModifierAsync` 在移动鼠标后不检查目标坐标处的顶层根窗口，
   只要 `SendInput` 返回发送数量就记录成功。它无法区分“游戏消费了点击”和“自己的悬浮窗
   消费了点击”。

管理员权限不是本次已证实根因；`SendInput` 成功也不等价于目标游戏实际消费输入。

## 最小修复边界

只允许处理本问题所需的输入安全契约：

- 自动刷开始前强制本程序的操作面板进入鼠标穿透状态，不能让跨版本持久化的 `false`
  阻断自动化；
- 组合键点击在发送鼠标按下前，用 `WindowFromPoint` 并解析根窗口，确认目标坐标属于当前
  游戏窗口；若被任意其他顶层窗口覆盖，明确失败且不发送鼠标点击；
- 无论成功或失败，都必须释放已经按下的修饰键；
- 保存可诊断的目标点、命中 HWND、期望 HWND 信息。

不得在本项修改：

- UAC 清单、注册表、组策略或计划任务；
- 游戏导航坐标、页面模板、识别阈值；
- 全局焦点等待时限；
- 悬浮面板布局、历史界面或识别业务逻辑；
- 用户筛选条件及其他设置。

## 验收边界

自动化测试通过只证明输入控制器与自身面板状态契约；最终仍必须启动正式程序，在真实
游戏中完成至少一次 `normal_hud -> guide_shell/guide_currency_wars` 页面切换，并验证：

- 即使启动前共享设置为 `false`，自动刷开始后也不会被自身面板拦截；
- 输入点被其他窗口覆盖时不会静默宣告成功；
- 游戏与程序权限级别匹配；
- 自动刷的后续点击、识别和停止功能没有回归。
