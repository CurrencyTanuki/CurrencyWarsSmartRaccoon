## 一、结论摘要

指令集 v4.3 在**零件划分**上是清晰的（I/A/M 分层、语义化参数、宏封装固定流程），但在**可执行性**与**内部一致性**上存在阻断级缺陷。

| 级别 | 数量 | 含义 |
|---|---|---|
| P0 阻断 | 2 | 会导致流程卡死或误触发"点了就全完"红线，**必须先修** |
| P1 严重 | 8 | 逻辑冲突 / 覆盖缺口，会导致行为偏离决策树或无法开工 |
| P2 应修 | 7 | 契约不完整、历史 bug 复发点未设防、过程数据泄漏 |
| P3 建议 | 4 | 序列缺失、术语与边界标注 |

**最核心的两个结论：**

1. **奇迹代偿血量红线阈值在三方权威源中口径冲突**（88 vs 89），且被审文档内部两处自相矛盾。这是文档自述"点了就全完"级别的安全闸，取错值即卡死流程。
2. **30 条指令中仅 12 条有明确触发者**，18 条调用点缺失或未定义（含 M2 晶矿、M6 环境选择、M8 通关至 1-3 三个宏）。指令集目前是"零件清单"而非"可执行规格"，重构者无法仅凭本文档构造决策层状态机，只能回读旧代码——而旧代码正是本次要重构的对象。

## 二、P0 阻断级

### P0-1 奇迹代偿血量红线阈值三方冲突（88 vs 89）

被审文档自身及两份权威源给出**互不相同**的红线：

| 来源 | 原文位置 | 拒选/危险线 | 选择线 |
|---|---|---|---|
| 被审文档·第二部分思想一 | L28 | **血 < 88** 会被游戏拒绝并卡死 | 血 ≥ 89 必选（L26） |
| 被审文档·M3 优先级表 | L174-175 | **血 < 89** 绝不选 | 血 ≥ 89 必选 |
| 被审文档·第三部分机制 | L83 | — | 仅血 ≥ 89 |
| 决策公理 20260830 | 第 3 条 | **血 < 89** 点奇迹代偿会被游戏拒绝并卡死 | — |
| 决策树定稿版 | F13(L158)/F15(L164)/F15a(L166)/L2(L188) | F15/F15a：**血 < 88** 才危险 | F13：血 **> 88**（即 ≥89）才选 |

**冲突点：**

- **被审文档内部自相矛盾**：思想一（L28）说 `<88`，M3 表（L175）说 `<89`。整数 **88** 在两处结论相反。
- **与决策公理冲突**：思想一的 `<88` 与公理第 3 条的 `<89` 直接矛盾，而公理是 2026-08-30 定稿、标题即"最高公理"。
- **决策树自身悬空**：F13 判定线是 `>88`（88 走"不选"），F15 的危险线是 `<88`（88 其实安全）。**血 = 88 在决策树里没有确定归属**，被审文档没有修补这个缝隙，只是把两种表述都抄了进来。
- **"识别失败"分支缺失**：思想一 L28 要求"识别失败按 <88 防御处理"，但 M3 表只有 `≥89` 与 `<89` 两行，**没有"未知/识别失败"行**；且该防御阈值本身沿用的是冲突中的 88。

**后果**：M3 的参数是"当前血量"，血量是奇迹代偿的唯一门槛——而奇迹代偿是两条终局路径之一。若实现者按思想一取 `<88`，则在血 = 88 时会判定"安全可选"并点击；若真实红线为 `<89`，则触发游戏拒绝、流程卡死，正是文档自称的"点了就全完"。

**建议**：

1. 全文统一为单一口径：**血 ≥ 89 必选；血 < 89（含 88）绝不选；血量未知按"绝不选"防御处理**。
2. 删除思想一 L28 的 `<88` 表述，改为 `<89`，并同步说明"88 亦在拒选区（保守侧）"。
3. M3 表补一行：**血未知/识别失败 → 绝不选（选另一侧）**。
4. 反向修订决策树 F13/F15/F15a/L2 的 88/89 混用，消除 88 悬空。

> 注：本条不需要实机验证即可判定为缺陷——三处文档互相不等价，且不等价区间恰落在安全闸上。

### P0-2 M3 补充规则与优先级表在特定组合下给出相反动作

- **M3 优先级表**（L174-181）按序匹配：第 2 条「奇迹代偿 且 血<89 → 绝不选 → **选另一侧**」
- **M3 补充规则**（L182）：「双侧同现关键试炼**取优先级高者**」

考虑组合：**一侧 = 奇迹代偿（血 < 89），另一侧 = 无限之釜（单人模式）**

| 依哪条规则 | 动作 | 结果 |
|---|---|---|
| 表顺序（第 2 条先命中） | 选另一侧 = 无限之釜 | 单人 → 收工 ✓ |
| 补充规则（取优先级高者） | 奇迹代偿序 1/2 > 无限之釜序 5/6 → 选奇迹代偿 | 血<89 点它 → **游戏拒绝、流程卡死** ✗ |

被审文档**未定义补充规则与表顺序的仲裁关系**（补充规则是"先于表"的前置筛选，还是"表内同序"的平局裁决？）。

**后果**：该组合在实机中可出现（3/4/5 档池同时含奇迹代偿与无限之釜）。仲裁歧义直接导致 P0-1 的卡死场景被触发。

**建议**：明确"**表顺序为唯一仲裁**；『取优先级高者』仅在双侧均**可选**（未被红线排除）时适用；被第 2 条排除的奇迹代偿不参与优先级比较"。

## 三、P1 严重级

### P1-3 顶层编排链缺失，P0 / M6 / M8 / M2 的调用顺序未定义

被审文档定义了 P0（L116-117）、M6（L164）、M8（L166）、M2（L160），但：

- **M8 内部流程不含 M6**（L166：「导航进1-1 → 通关1-1/1-2 … → 到达策略页选策略（M7）→ 进1-3备战页」）
- **M8 内部流程不含 M2**（第三部分 L104 要求"进 1-3 **先开晶矿**"）
- **M6 自称覆盖"整个刷开局阶段"**（L164），与 M8 的边界重叠且时序不明
- 第五部分"决策层状态机"（L184-192）只给了**常量推算 / 事件驱动规则 / 对账机制 / 终局判定**，**没有主流程链**

**后果**：重构者无法从指令集推出 `P0 → M6 → M8 → M2 → 1-3 运营循环` 的顶层序列，只能回读 `GrailRunLoop.cs`——而它正是本次重构要替换的对象。这与文档"重构三层交互方式"的目标直接冲突。

**建议**：补一节「顶层编排链」，显式写出各宏的调用顺序、衔接条件与失败跳转。

### P1-4 硬规则「1-1/1-2 购买预设禁用 + 银河学者启用」无任何指令承载

- 被审文档第三部分 L98：**「1-1/1-2：三仙舟+2DOT 购买预设禁用；银河学者（猫猫糕）启用（仅 1-1 生效）」**
- 决策树 N1（L31）① ② 同要求，且属用户原节点"一字未改"
- **I/A/M 共 30 条指令中，没有任何一条能操作"购买预设"或"策略开关"**
- M8 内部流程描述（L166）也未包含这两项

**后果**：决策树 N1 的两条配置在指令集里无处落地，1-1/1-2 阶段会沿用错误预设。

**建议**：补指令（如 `A13 购买预设开关` / `A14 策略开关`），或在 M8 内部流程中显式写明并标注依赖的底层组件。

### P1-5 I5 读血量 / I6 读金币 的调用时机未定义

- 对账机制（L191）：**「每执行若干指令后发 I3+I4」**——只列了备战席与上场名单
- **I5（血量）、I6（金币）、I7（星徽）均未被纳入任何对账触发点**

而这两项是最高权重输入：

- 血量 = 奇迹代偿唯一门槛，且是 M3 的入参（L161）
- 金币 = N17 买经验（8/10 金）、N18 刷新、S1A/S1B 卖人的全部判据

思想五（L47-52）描述了 last-known 缓存与陈旧度窗口，但指令集没有规定**何时触发刷新**——缓存没有补给入口。

**后果**：与 P0-1 叠加放大。M3 若拿到陈旧血量，在 88/89 边界附近误判即触发卡死。

**建议**：规定强制刷新点，例如"每次检测到祈愿弹框上沿 → 必发 I5（读当前血量）后再发 M3"；"每 N 次商店操作 / 每次卖人后 → 发 I6"。

### P1-6 M8 声明无参数，但内部流程需要购买白名单

- M8 参数列（L166）写 **"—"**
- M8 内部流程写「含商店**按白名单**买命杯成员」

**建议**：M8 增列 `白名单` 参数，或明确"M8 内部复用 M5，白名单由决策层注入并透传"。

### P1-7 星徽装配指令流不自洽，且与决策树 N2 时序错位

被审文档 L189：「I7 星徽>0 → 发 **A4 装配到最便宜备战席非命杯角色** → A1 上场」

两个问题：

1. **缺 I3 前置**："最便宜"需要备战席各角色的费用数据。指令集没有先发 I3（读备战席全量），决策层无数据来源。
2. **时序错位**：决策树 N2（L35）与 R19（L23）表明，**019 命运圣杯邀请路线的星徽是开局即得**，装配上场发生在**进入 1-1 之前**。而被审文档把该规则挂在"决策层状态机·事件驱动规则"（L186-190）——这是 1-3 运营循环内的规则。

**后果**：019 路线下星徽装配被推迟到 1-3，影响 2 档激活时机（N2 → N1 的升档链路）。

**建议**：显式写指令序列 `I7 → I3 → A4 → A1`；并单独规定"019 路线在 M8 阶段（进 1-1 前）即触发装配"。

### P1-8 M5 循环终止条件「刷新无效」未定义

M5 内部流程（L163）：「循环至**买到/名单齐/刷新无效**」

- 前两个是可判定的
- **"刷新无效"没有判定标准**：金币不足？连续 N 轮货架无目标？货架签名不变？均未定义

**这一点特别危险**：被审文档第五部分 L209 把「**刷新不生效空转**」列为**必须证明不复发**的历史 bug 之一，而这条未定义的终止条件恰是该 bug 最可能的复现路径。

**建议**：改为可判定条件，例如「金币 < 刷新价 → 停止」或「连续 K 轮货架角色签名不变 → 停止并上报」。

### P1-9 M6 / M3 内含决策层动作，违反思想二

思想二（L30-34）：决策层是司令官，宏只返回事实。

但：

| 位置 | 内容 | 越界性质 |
|---|---|---|
| M6 内部（L164） | 「再未中**弃局重开**（整个刷开局阶段循环直至命中）」 | 弃局 = 决策树 R3 级终局决策 |
| M3 表第 5 条（L178） | 「无限之釜+单人 → 选它 → **收工停机**」 | 收工 = 决策树 L7 终局决策 |
| M3 表第 8 条（L181） | 「四次用尽仍无关键试炼 → **弃局重刷**」 | 同上，R3 级 |

**后果**：终局判定出现**双重真值源**——宏内部一份、第五部分 L192 的 `GrailFinalJudge` 一份。且 M6 若真的"循环直至命中"，该宏可能永不返回。

**建议**：宏只回事实（"选中的试炼名"、"命中的环境 ID"、"四次是否已用尽"）；弃局与收工统一上收到决策层，由终局判定裁决。

## 四、P2 应修级

### P2-11 A10 参数「槽位号」违反思想二

思想二 L32 明写：**「绝不传坐标/像素/槽位号等过程数据——坐标全部写死在操作层」**，而 A10「选投资策略槽位」参数 = **槽位号**（L150）。

**建议**：改为语义参数（如策略名或优先级序号），槽位号由操作层解析。

### P2-12 M4 返回「落在备战席几号位」暴露过程数据

M4 返回（L162）：「拿到的角色名 + **落在备战席几号位**」。思想二虽只约束参数，但该槽位号下游并不需要（A1 部署用角色名），返回它只会诱导决策层依赖过程数据。

**建议**：去掉，或标注为"仅诊断用途，决策层不得使用"。

### P2-13 M4 终止依赖 LettersObtained 准确性，且无防错

- 历史审计 #12（AUDIT_FINDINGS L19）：「**LettersObtained 恒 +2（王之财宝等只给 1 本）→ L4 永不过、整局白跑**」
- 被审文档第三部分 L85 仍写「回路过载（**2 张**）」，M3 第 3 条触发 M4
- **I 类指令没有"读聘用书数量"，状态机无法核对实际本数**

**后果**：若实际只给 1 本而状态机记为 2 本，M4 会死等第二本书。

**建议**：M3 返回实际奖励本数；或扩展 I7 为"读物品栏（星徽 + 聘用书）"。

### P2-14 M3 第 3 条未排除「四费聘用书」

历史审计 #12 同条：「**四费聘用书与五费聘用书编辑距离 = 1 误匹配**」。被审文档 M3 第 3 条（L176）只写「奖励=**五费**聘用书」，**无排除条款**，未继承该修复。

**建议**：写明"精确匹配五费，显式排除四费聘用书"。

### P2-15 A6「买经验升人口」契约不完整

- A6 参数 = "—"（L145），**无金币参数** → 操作层无法自检
- 第三部分 L93：回路过载选中后买经验价 **+1/次** → 2 次实际需 **10 金**
- A6 描述「固定买 2 次 → 人口 5（已验证）」，**未提诅咒价，也未定义失败返回值**

**后果**：诅咒期间金币为 8~9 时，第二次点击会失败，而 A6 的返回契约无法表达"只买成 1 次"。

**建议**：A6 增金币参数，返回改为「实际买成次数 + 当前人口（已验证）」。

### P2-16 节点标识缺失，「不跨过 1-3」无可验证锚点

- 被审文档 L13/L92 自述：**1-1/1-2/1-3 布局全局一致**（`PreparationPageId` 统一）
- 因此 I1「识别当前页面」**无法区分 1-1 / 1-2 / 1-3**
- 指令集没有"当前节点"状态变量，也没有读节点的 I 类指令

**后果**：硬规则「不允许跨过 1-3 推进节点」（L100）、「1-1/1-2 禁止出售」（L94）只能靠流程位置推算。一旦 M8 异常提前返回，两条硬规则同时失去锚点。

**建议**：状态机显式维护"当前节点"，并在第五部分规定推进条件与校验点。

### P2-17 I8 与 M3 职责重叠

- I8（L130）「读祈愿弹框」返回 OCR 原文
- M3 内部流程（L161）同样"读弹框"
- 决策层事件驱动规则（L190）写「**I8/M3** 弹框 → 按 M3 优先级表应答」——把 I8 与 M3 **并列**

**后果**：决策层可自行 I8 后直接决策，绕过 M3，导致优先级表出现两处实现。

**建议**：明确 I8 仅供 M3 内部与诊断使用，决策层只发 M3。

## 五、P3 建议级

### P3-18 进 1-3 初始化序列缺失
