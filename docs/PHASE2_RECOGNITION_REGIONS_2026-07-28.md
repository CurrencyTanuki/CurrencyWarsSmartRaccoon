# 第二阶段对局状态识别区域（2026-07-28）

坐标格式统一为 `[x, y, width, height]`，相对于游戏客户区的 16:9 画面归一化到 0–1。所有区域在运行时换算为实际像素，不绑定 2559×1439 参考图。备战页面也就是本批截图中的局内主界面。

## 页面分类

| 页面 | 分类证据 | 采集频率 | 状态保存 |
|---|---|---:|---|
| 备战/局内主界面 | 备战阶段、前台区域、后台区域、购买经验文字与角色卡槽组合证据 | 2 秒 | 易变字段连续两帧一致后更新 |
| 战斗 | 右侧伤害榜标题、带单位伤害文字与伤害榜布局组合证据 | 3 秒 | 只在内存保留最新完整帧 |
| 战斗结束/离开战斗 | 连续两帧从战斗切换到非战斗页面 | 2 秒 | 仅落盘上一战斗的最后完整帧 |
| 未知 | 证据不足或冲突 | 2 秒 | 保留截图和不确定性，不写成确定状态 |

## 明确不采集

敌方组成、敌人名称/弱点/状态、战斗波次、选中敌人、我方生命和能量条、战斗增益减益、行动顺序与当前行动角色、角色头像右下角红黄数字、Boss 剩余阶段、战斗过程事件、暂停/加速、未来路线图标、UID、网络延迟、键位提示、场景特效和“本次总伤害”。

## 数据关联与证据

每次运行建立 `runId`；原始截图位于该运行的 `screenshots`；每份分析保存截图来源、时间、页面、节点、字段状态、置信度与不确定性。未知图标裁剪保存在 `unresolved-icons`。最终战斗记录按 `nodes/node-{节点}-final.json` 保存，包含角色伤害、伤害总和、剩余行动值以及最终证据帧时间。

## 后续真实场景验收

新图片库放入约定分类目录后无需改核心流程即可自动加载。真实场景测试时，对每张图执行程序分析，再由人工逐项读取原图，对照检查：读到且正确、读到但错误、画面存在但漏读、需求范围内但代码尚未实现。所有失败图加入回归集，未知结果不能通过降低全局阈值改成“已知”。
