# 审计方法论：双通道推理流（2026-09-08，用户令）

> 起因：用户指出"你先找日志异常、再拿画面去验证——有些异常日志里根本不写；而这些隐藏问题肉眼很容易看出来"。
> 本文档把正确做法固化为可执行流程。与 rule.md 第八节（监督断言清单）配套：第八节回答"对照什么"，
> 本文档回答"按什么顺序、走什么通道、怎么推理"。违反本文档=审计未做。

## 〇、根因：日志通道的结构性盲区

日志只记录**软件自己的动作与自我报告**。三类问题在日志里**天然不存在**：

1. **静默状态错误**——游戏真实状态错了但软件没有任何动作（矿没开=没有 M2 行、徽没装=没有 A4 行、
   学者站场上=没有处置行）。"没有那行日志"本身才是异常，扫描"已有的行"永远看不见。
2. **回执与效果脱节**——动作记了、回执 OK，游戏侧没生效（A2 卖卡 OK 但卡还在）。
   日志只能暴露"回执自相矛盾"，不能暴露"回执与画面矛盾"。
3. **界面/时序状态**——卡在某页面、商店收不掉、弹框被谁吞、动画期读数——画面上一眼可见，
   日志里只是正常的轮询心跳。

肉眼容易看出来，正因为肉眼读的是**状态**；日志难看出来，因为日志只有**动作**。
所以：**审计状态必须走画面，审计动作才走日志**。二者是两条独立通道，不是主次关系。

## 一、总原则（一句话）

**日志是嫌疑名单，画面才是地面真值。两条通道独立作业、各自产出结论，再强制双向对照——
任何一条通道单独的"干净"都不构成结论。**

禁止的旧做法（本次被用户抓的）：日志异常 → 挑对应画面"验证" → 画面沦为日志结论的证人。
正确做法：画面独立重建盘面时间线 → 日志独立重建引擎意图 → 双向对差。

## 二、通道 A：画面重建（自下而上，先于看日志）

对每一局（run 目录），**禁止先读该局日志**，按以下步骤：

1. **按节点锚定抽帧，不按日志异常抽帧**。固定锚点清单（每局都抽，无论日志多"干净"）：
   - 进 1-1 首帧（M8 停靠态）
   - 1-1 出战前（人数、阵型、星徽装了吗、矿开没开）
   - 1-2 商店/出战前
   - 1-3 策略页（选中的策略在第几槽）
   - 1-3 清场完成帧（前台剩谁/备战席剩谁/试用卡几张/商店状态）
   - 每次祈愿弹框帧（两侧各是什么、点了哪侧）
   - 判死/弃局前最后一帧
   - 另加：按时间均匀随机采样（防"只在节点看"漏掉节点间卡死）。
2. **逐帧重建盘面**：金/血/等级/人口/前台卡(谁、什么状态)/备战席卡/羁绊面板数字/界面所在页/模态。
   读不出的项如实标"不可读"，禁止脑补。
3. **串成画面时间线**：游戏真实经历了什么。
4. **画面时间线内部找异常**（不看日志也能看的）：
   - 该出现的状态没出现（矿球、星徽、上场卡）
   - 状态该变化而静止（同页面长时间、同一张卡反复出现）
   - 界面停留异常（商店收不掉、结算页压着、弹框悬空）
   - 卡面轮换/位移异常（试用卡轮换、卡被系统移动）

## 三、通道 B：日志重建（自上而下）

1. 从日志重建**引擎意图时间线**：软件以为盘面是什么状态（它认为谁在场/多少金/什么页）、
   它做了什么、它为什么做（指令=意图）。
2. 与通道 A 完全独立地记录，禁止中途用 A 的结论修正 B 的读法。

## 四、双向对照（核心步骤，三张差表）

1. **模型差**（画面 vs 引擎认知）：每一步"软件以为"对照"画面实际"。
   实锤案例：引擎两次对"在场 F2 黑塔"执行出售，画面显示黑塔在备战席区域、卖出后原地不动。
2. **规则差**（画面 vs rule 断言）：游戏真实状态直接对照 rule.md 的"必须/绝不/仅当"。
   实锤案例（历史）：4 个 019 局星徽全未装配、金矿没开——日志全程 OK 零异常，画面一眼可见。
3. **事件差**（画面有、日志无 = 日志盲区实锤；日志有、画面无 = 执行失败实锤）：
   画面里明显发生了变化而日志无对应动作行；或日志发了指令而画面无痕迹。

## 五、反向红旗清单（主动找"日志不写的问题"）

每局必答，答案为"是"即红旗，无论其他计数多干净：

- [ ] **零动作红旗**：本局内某类**应当出现的动作类型**计数=0 或远低于理论值？
  （例：019 局 A4=0；命杯局 M3 应答数 << 理论祈愿档数；1-3 局清场卖出数=0）
- [ ] **静默等待红旗**：日志安静的时段，画面里游戏在等什么？（同一页面停留时长游程统计）
- [ ] **OK 洪水红旗**：全 OK 段落随机抽 1-2 帧画面对照（OK 洪水≠正确）。
- [ ] **血/金曲线红旗**：从画面序列读金/血，变化无对应动作解释的（+钱无来源、扣血无战斗）。
- [ ] **复核假反证红旗**：卖出/部署复核报警，画面验证到底是"卖了没生效"还是"复核查错位置"。
- [ ] **上下文前提红旗**：本局 goal/节点/阶段前提先核对（13a 教训：单人模式永不策略弃局）。

## 六、推理纪律（在 rule.md 8.1 六条之上追加）

1. **第四问**：逐操作三问（该做吗/做对了吗/失败处置对吗）之后必加第四问——
   **"画面和日志说的是一回事吗？"**不一致=至少一方在撒谎，以画面为准重新定性。
2. **同局双路径对照**：同功能两条路径在同一局的行为差异是最强证据，不需要跨局对照。
3. **不编造机制**：画面看不懂的（如试用卡规则）如实标"机制盲区待拍板"，禁止用合理推测填空。
4. **通道覆盖度必须声明**：报告里逐局标注走了哪些通道。只走日志通道的局，
   必须标注"画面未审"——**没走画面通道的审计不完整，不可下"无问题"结论**。
5. **抽样透明**：抽了哪些帧、为什么抽这些、漏了哪些段，全部列出（防选择性取证）。

## 七、落地形态

1. **抽帧工具**：run 截图按本文档锚点清单自动挑帧+按局拼"时间线墙"（一屏多帧缩略）供目视，
   目标=一局 10 分钟内完成通道 A。
2. **扫描器扩展**：第五节红旗清单中可执行化项（动作类型计数=0 检测、页面停留游程、
   血金曲线无来源变动）并入 sweep 扫描器；不可执行项（画面级）保持人工。
3. **引擎内断言**：凡"画面才能发现"的状态，尽量转成引擎可感知断言（如携带者坐板凳），
   但诚实承认上限——界面状态、卡面轮换只有画面能看见。
4. **报告格式增补**（在 8.3 之上）：必含"模型差/规则差/事件差"三张差表（空表也要交）
   +逐局通道覆盖度声明+红旗清单答题记录。
