## 一、项目是什么

**货币战争智能狸**（CurrencyWarsSmartRaccoon）是一款 Windows 桌面辅助工具，为《崩坏：星穹铁道》的**「货币战争」**玩法（独立于模拟宇宙体系的常驻玩法，非分支）提供：

1. **局势数据记录**（核心差异化）：自动识别并记录每个节点的阵容、装备、经济（金币）、伤害、行动值、血量历史，支持悬浮看板（Overlay）与挑战总结报告（HTML）。
2. **开局小助手**：快速刷开局（标准博弈盲点连点路径）。
3. **设置页**：角色保留/自动购买、出售策略、投资环境/策略筛选等。
4. **局势分析（骨架）**：AdvisorEngine 可解释建议（尚未接真实攻略数据）。

**技术栈**：C# / .NET 8 / WPF（App）+ WinForms 兼容层（Vision）+ OpenCvSharp（模板匹配/图像处理）+ PaddleOCR（离线中文 OCR）+ Windows.Graphics.Capture / GDI 截图。

## 四、云游戏适配技术方案（重点：本次交接的核心）

### 背景问题
用户主要在**云游戏（Edge 浏览器打开星穹铁道云游戏）**下使用。云游戏窗口有两大问题：
1. **截图黑屏**：云游戏用 GPU 合成渲染，`BitBlt`（GDI 截图）常得到全黑/深灰画面。
2. **定位后窗口乱动**：旧方案定位时把窗口切前台 + 用后台截图预览，但**切前台会让云游戏浏览器从全屏还原/缩小**（窗口乱动），且后台截图黑屏。

### 解决 1：截图黑屏 → GdiGameCapture 的 PrintWindow 回退
文件：`src/CurrencyWarsAssistant.Vision/GdiGameCapture.cs`

- 先用 `BitBlt` 从窗口 DC 截取。
- 若 `IsEffectivelyBlack(pixels, w, h)` 判定为黑/深灰（RGB 阈值 60，只采样中心 60% 区域——云游戏坏帧特征：中间深灰 RGB(32,32,32)、边缘有 UI），则**回退用 `PrintWindow(hwnd, dc, 2 /* PW_RENDERFULLCONTENT */)`** 截取 GPU 合成内容。
- 阈值 60 的来历：云游戏坏帧是深灰 RGB(32,32,32)，原阈值 24 判不出（32>24）→ 不触发回退 → 用了坏帧。放宽到 60 后深灰坏帧能触发回退。

### 解决 2：定位窗口乱动 + 按钮不显示 → QQ 截图式全屏遮罩框选
文件：`src/CurrencyWarsAssistant.App/GameAreaCalibrationWindow.xaml(.cs)` + `MainWindow.xaml.cs` 调用

**旧方案（0.2.815 稳定版）的问题**：
- 定位时 `BringWindowToForeground` **把云游戏浏览器切前台** → Edge 从全屏还原/缩小 → **窗口乱动**
- `LoadPreviewAsync` **后台截图预览**（云游戏 GPU 合成，BitBlt 全黑）→ 预览画面是黑的
- 1100×760 的**独立模态小窗口** + "确认游戏区域"按钮 → 在 2560×1440+150% 缩放下**超出屏幕**、按钮被遮挡/点不到 → **"按钮不显示"**

**新方案（0.2.822+，QQ 截图式）**：不切浏览器前台、不用后台预览、**没有按钮**——弹出覆盖整个屏幕的半透明遮罩窗口，在遮罩上直接框选：

1. `MainWindow.xaml.cs` 的定位入口：
   - **云游戏浏览器不切前台**（`selected.SourceKind != CloudBrowser` 才尝试 `BringWindowToForeground`）——因为切前台会让浏览器从全屏还原/缩小。
   - 用 `CaptureFrameLoader`/GdiGameCapture **后台截图**获取当前窗口画面（此时 PrintWindow 回退已生效，能截到真实画面）。
   - 创建 `GameAreaCalibrationWindow`，`Owner = null`（独立窗口，避免模态抢焦点），`Show()` + `Activate()`。
2. `GameAreaCalibrationWindow`：
   - **全屏遮罩**：`WindowStyle=None + ResizeMode=CanResize + AllowsTransparency=True + Background=Transparent + Topmost=True + ShowActivated=False + ShowInTaskbar=False`。
   - 把后台截图（真实游戏画面）作为 `OverlayBackground` 画在 Canvas 上，定位到窗口真实屏幕位置（`originX/originY`）——让遮罩窗口**精确覆盖在游戏画面上方**，用户透过半透明看到真实画面。
   - 鼠标事件：`PreviewMouseLeftButtonDown/Move/Up` 实现**框选矩形**（QQ 截图式拖拽），`UpdateSelection` 实时画选区。
   - 松手后：**自动校正为 16:9**（用选区中心 + 16:9 比例计算最终矩形），返回框选区域给 `MainViewModel` 保存为 `HostClientAreaOverride` / `_savedGameArea`。

### 相关关键点
- `GameWindowInfo.HostClientAreaOverride`：定位时框选的游戏区域（覆盖默认 ClientArea）。
- `WindowsGraphicsGameCapture.CopyFrameAsync`：用 `surfaceScreenArea`（窗口屏幕区域）做坐标换算，把窗口表面裁成游戏区域。**注意：当前版本已回滚掉"crop 越界自动重算"逻辑**（曾加的窗口自适应重算/16:9 自动裁剪已按用户要求回滚，恢复为越界即抛异常"已定位的游戏区域不在当前窗口捕获表面内"）。这是**有意的**：用户反馈云游戏窗口移动不是根因，根因是备战页识别失败，勿重新引入。

### 备战页识别修复（0.2.824）详细根因
- **症状**：用户打到 3-1，软件还停在 2-7（漏结算/备战节点）；或在备战页停留很久一直"画面已变化"/"无法可靠识别"。
- **诊断方法**：用用户的云游戏备战页截图（2559×1439）跑 `GamePageClassifier` 锚点匹配，输出每个锚点分数（临时诊断测试 `CloudGameDiagnosticTests`，已删除）。
- **结果**：云游戏备战页 `preparation_stage_1_2` 锚点匹配 **83.8%**，原阈值 **0.9（90%）** → 匹配失败 → 页面判 Unknown → `Phase2OperationalStateTracker` 的"必须回备战页才封存"条件永不满足 → 卡死。
- **修复**：`config/page-recognition.1920x1080.json` 里 `preparation_1_1`/`preparation_1_2` 的锚点阈值 0.9 → **0.8**。改后两张云游戏备战帧（1-2、1-3）均正确识别（83.8% / 95.9%）。
- **防回归**：`PreparationRealFrames_AreClassifiedAsPreparation` 等真实帧回放测试全通过；全量 651/651。

## 六、已知未解决问题（下一步方向）

1. **节点号读错**（1-3 读成 1-2）：模板只有 `preparation_1_1/1_2`（无 1_3+），节点号由数字 OCR 读 `PreparationNodeValue` 区域；云游戏画质下数字 OCR 读不准。需加 1_3+ 模板或改进数字识别。
2. **金币/数字读错**（22→2、37→7）：`UiDigitSequenceRecognition` 字形分割在云游戏画质下把多位数拆错/读错。数字识别深水区，需用云游戏真实帧诊断后专项修。
3. **行动值识别错误**：游戏 bug 显示错误（最后几帧行动值不可信），且云游戏画质下识别错（100 行动值误报）。
4. **姬子启行/昔涟终结技动画**：伤害页签被隐藏，但节点页签在——"必须回备战页才封存"已保证不误封存战斗帧；但动画期间持续 Unknown，识别恢复依赖画面变化。已有防护，未完全解决。
5. **云游戏窗口最小化期间无帧**：Windows.Graphics.Capture 在窗口最小化时不产生帧，记录暂停（系统限制，无法避免）。
6. **云游戏非精确 16:9**：客户区 2559×1439（Edge 全屏少 1px）；`IsSixteenByNine` 允许 ±1px 容差，正常通过；但 2544×1432 等非 16:9 客户区会触发"不是16:9"警告（用户需调整云游戏画面比例）。
