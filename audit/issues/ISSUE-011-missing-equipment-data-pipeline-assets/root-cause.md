# ISSUE-011 根因与最小修复边界

## 根因

这是交接源码完整性问题：测试和数据导入文档保留了装备转换管线契约，但 20260808 源码包漏掉 `tools/Invoke-EquipmentDataPipeline.ps1` 及脚本唯一读取的五份 equipment schema/map。数据原料与已生成 runtime 仍在，所以程序运行时可读取现有产物，但无法重建、审计或验证这些产物。

五个测试失败是同一缺失资产根因：成功路径找不到脚本；四个错误输入路径也无法启动脚本，自然没有规范的拒绝报告。

## 最小修复

只从两个哈希一致的历史来源恢复六个静态文件：

- 一份 PowerShell 转换脚本；
- `schemas/game-data/1.0.0/equipment` 下五份 schema/map。

不修改：

- C#、项目文件或测试断言；
- raw、runtime、图标、装备 ID/名称、分类或映射内容；
- App 发布复制规则；
- 识别、存储和两个历史界面。

## 验收边界

本项只恢复装备数据管线的可执行性、确定性输出和 schema 拒绝报告，不等同于完成 157 项装备图标与中文名称的视觉/网络交叉核对。该专项必须在本项通过后另行逐项执行。

历史材料中还有 `tools/Stage-EquipmentRaw.ps1`，但它不是当前五个失败测试或转换脚本的依赖；`schemas/advisor` 也属于另一条 App 资产链。两者继续标记为独立缺口，本项不得扩大宣称为“整个源码包或完整 staging 管线已恢复”。
