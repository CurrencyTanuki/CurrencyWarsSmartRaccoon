# 《货币战争》第一阶段重构规则账本

更新日期：2026-07-27

本文是重构后的第一阶段权威需求入口。规则来源不只包括旧需求文档，还包括当前生产调用链、配置、自动化测试、真实截图 fixture、实机迭代记录和历史修复报告。旧的 `config/opening-rules.json`、`config/recognition.json`、`config/screen-layouts.1920x1080.json` 以及 `OpeningRuleEvaluator`、`OpeningRerollTask`、`TemplateOpeningReader` 不属于生产权威路径，只能用于追溯。

## 1. 产品范围

核心第一阶段闭环：普通 HUD → 指南 → 货币战争主页 → 模式选择 → 职级难度 → 敌人概览 → 位面流程 → 投资环境 → 1-1；不合格时安全放弃并结算，返回主页开始下一轮。

现有程序还把 1-1 布阵、前两层奖励关、商店、晶矿、出售和首个投资策略接在同一个自动重刷入口后。为避免删除现有功能，新架构将其定义为“可选奖励扩展”：与核心重刷分层，但保留开关和全部现有用户规则。标准模式运行两层奖励关，超频模式运行一层。

自动模式没有总轮数和总时长上限；这不允许任何单个等待、识别、点击或恢复无限执行。每个动作必须有前置状态、成功后置条件、失败条件、有限预算和安全出口。单次观察模式最多一轮、活动时间最多三分钟，并停在投资环境页。

## 2. 开局判定

所有 ID 比较不区分大小写。

### 2.1 全局条件

- 投资环境只允许正选；多个正选为 OR；空表示不限制。
- 敌方阵营与负面词条支持“不限制 / 必出 / 刷掉”。同一全局类别里的多个必出项为 AND，任一刷掉项出现即失败。
- 全局投资环境、阵营、词条和特殊组合彼此为 AND。
- 首次完整识别没有出现偏好投资环境时，只使用一次免费刷新；刷新后仍无偏好则本轮失败。
- 投资环境识别不完整时可任选已知候选进入 1-1，但本轮必须按失败重开，不能猜测命中。
- 敌人识别不完整时，旧行为会保留连续确认项；正选缺项会失败，但未知黑名单项可能被视为未出现。该不对称暂为兼容行为，列为待确认风险。

### 2.2 特殊组合

- 一个组合可同时包含投资环境、阵营和词条。
- 组合内所有已配置条件为 AND，只有完整出现才算命中。
- `Required` 表示完整命中才通过；`Reject` 表示完整命中才失败；部分出现不得触发。
- 启用的空组合是无效配置；禁用的空组合无效果。
- 内置规则稳定 ID 为 `death_dragon_plus_extra_strike`，当前名称为“灰手生命科技 + 额外打击”，条件是 `competitor_12` 与 `enemy_affix_t2_16`。
- 自定义组合具有持久化稳定 ID；开关不得把 `Required` 偷换成 `Reject`。

### 2.3 多套刷取方案

- 一个方案内部类别之间为 AND。
- 方案内投资环境正选、阵营正选、词条正选各自为 OR；排除项全部必须不存在。
- 多个启用方案之间为 OR。
- 全局条件与启用方案的现行关系是 AND，而不是互相替代。
- 同时命中多套方案时随机锁定一套；后续投资环境与投资策略只能来自被锁方案，禁止跨方案拼接。
- 投资策略只影响奖励扩展，不参与初始开局判定。因此“只配置投资策略”的方案会接受任意开局；此行为保留但仍需产品确认。

## 3. 用户配置与默认值

| 配置 | 默认值 | 作用 |
|---|---:|---|
| 游戏模式 | 标准 | 标准两层奖励、超频一层 |
| 未知页 Esc 恢复 | 开 | 非战斗未知页最多三次受控恢复 |
| 命中后完成奖励扩展 | 开（兼容旧用户） | 1-1 后继续布阵和奖励流程 |
| 三仙舟 + 2DOT | 开 | 买入低费候选并禁止自动出售 |
| 银河学者猫猫糕 | 关 | 只在 1-1 前尝试两名不同角色同时上场 |
| 备战席出售 | 不出售 | 可选全卖或只在能跨 10/20 利息档时卖 |
| 用户逐角色保留 | 全关 | 所有副本可买且永不出售，不自动获得上场资格 |
| 用户逐角色自动买 | 全关 | 常规商店购买清单 |
| 日志悬浮窗 | 开 | 最多显示七行运行日志 |
| 日志鼠标穿透 | 开 | 不阻挡游戏输入 |
| 日志透明度 | 0.52 | 有效范围 0.25–1.0 |

三组全局筛选、Profiles、内置和自定义特殊组合、奖励规则、角色清单、模式与悬浮窗设置均须持久化。运行开始时生成深拷贝快照，运行中 UI 改动不影响当前任务。

## 4. 自动化状态与安全约束

- 页面必须连续两帧稳定；开局 OCR 槽位至少两票且第一名不得与第二名并列。
- 页面轮询 300ms；初始识别 10s；导航活动预算 180s；敌人/投资环境 OCR 最多 30s；相同不完整签名连续六帧停止无效 OCR。
- 未知页最多三次 Esc，每次之后重新分类；已知但非预期页面不得盲按 Esc。
- 失焦暂停，重新获得焦点并稳定后恢复；暂停时间不计活动超时。
- 已有对局 `rank_difficulty_in_progress` 必须零输入并转只读监测。
- 同一导航失败指纹连续三次，或单轮导航累计六次后停止输入；自动模式进入被动监测，安全入口连续两帧出现后才重新接管。
- 放弃危险点击前必须稳定识别 `abandon_settlement_prompt`。
- 放弃结算最多两轮，每轮最多五次；结算 Next 最多十二次。耗尽后返回失败，由只读恢复接管。
- 商店打开/关闭最多三次；关闭后的未知过渡最多等待十秒。
- 每次购买只点击一次，并在十秒内验证：原槽角色连续两帧消失，或备战页连续两帧出现。原槽连续两帧仍在视为金币不足或操作未生效，本批次停止；不继续购买其他角色，不重复点击原槽。
- 金币无法稳定识别时不得执行依赖金币的利息出售；达到阈值时不卖；只有总出售价值能跨到 10/20 档时才卖。

## 5. 识别算法保留清单

- `WindowsGraphicsGameCapture`：持久 WGC 会话、三秒等帧、硬件 D3D 失败后 WARP、一次会话重建。
- 1920×1080 参考坐标；模板宽高比误差不超过 0.01；16:9 帧归一化后匹配并映回源坐标。
- OpenCV `CCoeffNormed`；可选灰度和 Canny(80,180)；页面所有锚点都必须过阈值，先按优先级再按平均置信度。
- `normal_hud` 使用失败截图迭代得到的 60×38 边缘模板与 0.52 阈值。
- Windows 本地 `zh-Hans` OCR 串行化；原图、阈值 150 反色、阈值 182 反色三种预处理，最长边 2400、1–3 倍放大、28px padding。
- 三个阵营固定 ROI；负面词条采用动态整行收窄、精确嵌入、保守模糊和五个 50% 重叠窗口 fallback，最终必须恰好四个不同 ID。
- 投资环境三个固定 ROI，失败时扩大上下文，并允许通过说明文本反查。
- 多变体投票、同支持且置信差小于 0.08 时拒绝歧义；不完整、重复或超额结果保持 Unknown，不猜。
- 角色卡、金币模板、商店 OCR、晶矿 Hough 和自动战斗 HSV 作为奖励扩展保留，不进入核心开局判定。

## 6. 冻结 UI 边界

`OperationPanelWindow.xaml/.cs` 与 `LogOverlayWindow.xaml/.cs` 的尺寸、颜色、布局、Topmost、不激活、鼠标穿透、拖动柄和透明度语义均冻结。本次重构没有修改这些文件。主界面继续以首页承载日常目标、方案、特殊规则、开始/停止；系统设置承载日志、恢复和奖励扩展开关。截图后端切换和可视化 ROI/阈值校准尚未实现，见风险清单。

## 7. 待确认事项

1. 新安装时奖励扩展是否应默认关闭；当前为了兼容旧行为仍默认开启。
2. Profiles 是否应继续与全局条件 AND，还是启用后替代全局条件。
3. 方案内多个“必出”正选为 OR 的命名是否需要调整。
4. 只配置投资策略的 Profile 是否应无条件接受任意开局。
5. 敌人部分识别时，未知黑名单项是否应强制整轮重开。
6. 是否允许自定义组合使用 `Required`；领域支持，快捷 UI 默认创建 `Reject`。
7. 截图器是否允许用户在 WGC 与经实机验证的 GDI fallback 间切换。
