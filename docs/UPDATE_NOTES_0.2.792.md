# 0.2.792 更新说明（2026-08-03 傍晚）

## 用户实测 0.2.791 后自查审计结论

用户反馈：①"页面仍然识别未知节点"；②"又有一个或几个逻辑被你改坏了，自己查"。
逐项自查 0.2.790/0.2.791 全部改动，确认三类问题并修复（均保守，不改识别输出）：

### 1. 备战页"进入备战节点 未知节点"（10:14:13 实测日志）
- **根因**：实机 2560×1440 下备战页模板置信度在 85%~92% 间波动（导航日志
  10:14:08 实测 85.4%）。导航靠 2 帧稳定确认兜底（最终 90.2% 通过），
  但只读收集器（Phase2LiveCollectionService）是**单帧**——分类器 miss 时
  `classifiedPageId=null` → 传入 `__classifier-miss__` → 节点解析失败；
  且该帧 OCR 读顶部节点区域也失败（qianwen 占 CPU 34% 时 OCR 3 倍变慢）。
- **修复**（两处）：
  - `SituationScreenshotAnalysis`：分类器 miss 但 operational 判定 family 已知时，
    PageId 回填用可解析 ID（preparation_generic/battle_generic/challenge_success）
    而非 "Preparation" 字符串，使页面证据语义一致；
  - `Phase2OperationalStateTracker.PageTransitionMessage`：备战页节点未知时
    文案改为"进入备战节点（节点号待确认，识别中）"，不再显示刺眼的"未知节点"。

### 2. 备战席角色识别错误（0.2.790 引入，用户 8/3 上午实测"远坂凛/三月七/翡翠"）
- **根因**：0.2.790 把 `InitialPreparationSettleDelay` 从 1400ms 砍到 800ms——
  识别在入场动画未稳定时开始，角色卡模板匹配置信度暴跌（实测 66%~74%），
  把花火识别成希儿/大丽花/爻光等。**这是 0.2.790 唯一真正"改坏"的逻辑**。
- **修复**：回退 6 处动画稳定类等待至 0.2.789 原值：
  - InitialPreparationSettleDelay 800→**1400ms**
  - 商店补员后 600→**900ms**
  - 银河学者替换后 350→**500ms**
  - 页面确认帧间 150→**200ms**
  - 金币复核帧间 200→**300ms**
  - 占用复核帧间 200→**300ms**
- **保留**：部署/出售后 AfterActionDelay 350ms（有 VerifyMoveAsync/
  VerifyBenchSlotEmptyAsync 验证兜底，风险低、收益在）。

### 3. 快速路径 8 秒超时（10:13:31、08:25:27 两次实测）
- **根因**：快速路径点"开始货币战争"后可能出现弹窗（update_popup/score_popup），
  `FastWaitForPageAsync` 只等目标页、不处理弹窗 → 8 秒超时。
- **修复**：快速路径轮询检测到弹窗时发送 Esc 关闭后继续（与常规路径的
  UnknownPageEscapeRecovery 语义一致）。
