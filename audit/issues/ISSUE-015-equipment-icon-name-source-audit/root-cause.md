# ISSUE-015 根因与处理决策

## 结论

“157个本地图标普遍与名称错配”的假设没有成立。静态哈希、远程字节、逐图视觉和重复簇关系共同表明：当前本地157条记录内部没有发现明确图标—名称错位。

实际发现的根因分为三类：

1. **共享图标的固有身份歧义**：47个哈希簇覆盖107个ID。普通/特权、命运改件、骇客改件和白昼羁绊变体共享图标，不能用像素强制识别成唯一ID；必须保留 `CandidateIds`/Unknown。
2. **来源级分类不完整**：垃圾袋、金垃圾袋的上游类型是 `？/？？？`，本地将其映射为 `special_material`。官方仅确认它们属于装备，没有提供本地枚举的精确分类名。
3. **数据覆盖说明与可复核来源不一致**：交接称总表158条并把财富×2定为误列；固定 revision 99085 实际有159行，Fandom也保留两条Wealth。专家邀请函可由官方“战利品”分类排除，但财富缺少上线后实机证据，不能裁决。

## 为什么本项不修改生产资产

- 157个现有图标均与工作副本、交接两份资产及远程声明字节一致；没有找到可证明应替换的具体图标。
- 直接新增或删除财富会把来源冲突变成未经证实的产品决定，违反“不猜测、可追溯”的要求。
- 修改垃圾袋分类同样缺少来源端精确枚举依据。
- 共享图标不是素材损坏；正确处理点在识别后的歧义保存与展示，已有部分逻辑但仍需后续端到端验收。

因此本项只交付审计证据与清单。财富覆盖、分类真值、识别→存储→两历史界面玩家可读展示分别进入后续独立问题，一次只处理一个根因。

## 回归风险

本项未改 `src/`、`tests/`、`data/`，不会改变程序运行。唯一风险是审计结论被误读：

- “远程SHA一致”不是“官方名称确认”；
- “视觉合理”不是“官方逐项证明”；
- “157条内部完整”不是“来源世界中绝无缺项”；
- “共享图标已解释”不是“识别可以返回任意一个具体ID”。

最终工作簿与文档已把这些边界写在摘要、逐行来源、冲突/边界和重复簇风险列中。
