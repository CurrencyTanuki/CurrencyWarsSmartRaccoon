# 《货币战争助手》第二阶段：4.4 攻略原始数据采集

你在另一台电脑工作，与主项目文件不互通。本轮只负责联网研究和生成上游原始攻略数据，不开发程序，不修改 Schema，不生成 runtime 数据。

## 目标

联网收集《崩坏：星穹铁道》“货币战争/零和博弈”4.4 版本的真实攻略，覆盖视频、文章和帖子。建立可追溯、可重复导入的原始资料层，让后续 Advisor 能理解一套攻略如何从开局逐步构筑阵容，以及不同阶段何时做什么。

## 数量要求

1. 建立至少 20 条去重后的候选来源索引。
2. 从中选择至少 10 篇信息完整的攻略，分别生成 `source-record.json` 和 `guide-raw.json`。
3. 至少覆盖 5 种不同流派或构筑方向；同一作者的重复转载不能充数。
4. 视频攻略必须记录关键时间码；文章/帖子必须记录章节、段落标题或可定位摘记。

## 必须遵守

- 一篇来源对应一套独立攻略，禁止把不同作者观点融合成“统一答案”。
- 使用 `schemas/` 中的契约和 `templates/` 中的样例；不擅自改字段含义。
- 游戏版本无法确认时写未知和判断依据，不得猜成 4.4。
- 保存作者、原链接、平台、标题、发布时间、访问时间、内容类型、版本、定位信息和版权状态。
- 攻略内容使用原创转述和结构化总结；不得打包完整视频、完整字幕、整篇原文、大段复制或博主图片。
- 版权未知时标记为 `linked_only`；保留原链接，不下载受限内容，不绕过登录、付费、DRM 或频控。
- 角色、羁绊、投资环境、投资策略如果无法对应稳定 ID，保留原文名称并标记待映射，不自造生产 ID。
- 只写 `output/`，不得覆盖 `schemas/`、`templates/` 或 `tools/`。

## 每篇攻略需要提取

- 目标流派、核心角色、替代角色、关键羁绊。
- 开局接受条件与应放弃条件。
- 投资环境、投资策略的优先级及排除项。
- 1-1、1-2、早期、中期、后期各阶段应该做什么。
- 购买、刷新、升级人口、保留金币、出售、转型的触发条件。
- 阵容成型标准、缺件时的替代路线和失败恢复路线。
- 作者明确表达的风险、例外和版本限制。
- 每条关键结论对应的视频时间码或文章定位。

## 输出目录

```text
output/
  source-index.json
  sources/<source-id>/source-record.json
  guides/<source-id>/guide-raw.json
  reports/RESEARCH_REPORT.md
  reports/VALIDATION_REPORT.md
```

`RESEARCH_REPORT.md` 必须列出：来源总数、完整攻略数、流派覆盖、无法访问的来源、版本不确定项、ID 待映射项、作者观点冲突、版权风险和建议的下一批采集方向。

## 验收标准

1. 每个完整攻略都能追溯到作者、URL 和具体定位。
2. JSON 全部可解析，并符合随包 Schema；无法表达的上游内容放入明确的原始备注字段，不要静默丢弃。
3. 不存在跨作者静默融合、伪造 ID、伪造版本或大段受版权保护原文。
4. 最终把整个任务目录压缩为 `phase2-guide-research-4.4-result.zip` 返回，不要只发文字总结。

完成后只汇报：ZIP 路径、来源数量、完整攻略数量、流派数量、验证结果和未解决风险。
