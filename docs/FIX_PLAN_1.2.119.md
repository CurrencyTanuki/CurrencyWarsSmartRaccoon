# 1.2.119 修复方案(已按对抗审查 PASS after fixes 修订;修订内容见文末"八、审查修订记录")

> 依据:docs/RE_AUDIT_20260907.md 全量逐局重审(22 命中局+晨班+1.2.118 窗口)七簇根因。
> 用户核心质问:**"为什么软件在某一操作之前停滞很久才执行?"**——本方案第一节先回答它。

## 一、停滞分类学(用户问题的正面回答)

全量审计测得的"操作前长时间停滞"共六类,全部有日志定量:

| 类 | 现象 | 定量 | 根因 |
|---|---|---|---|
| ①弃局 Esc 空转 | 弃局时每 40 秒按一次 Esc,反复十几轮 | 15 段合计 ≈117 分钟(窗口 47%),最长 23 分钟 | Esc 打在 **Esc 无效的页面**(投资环境选择=强制模态/祈愿弹框=模态/备战页=不该弃),弃局链不看页面身份,永不换策略 |
| ②快照等待税 | 进新节点后引擎"发呆"30-68 秒 | 每局 1-3 次(38s/50s/68s 实测) | 等待=固定退避梯烧完(5s 窗+12×5s 长尾),**不看"画面已就绪"的正面信号**,也不区分"永远等不到"(弹框在屏) |
| ③A4 出战失败死等 | 点选装配后出战失败,引擎报"等待外层重试或人工结算" | 15.2 分钟×2 例(局 12/13) | 出战失败处置链没有恢复动作(Esc+验页+重试),只有无限等待 |
| ④M3 探针固定税 | 部署后连发 8 次祈愿探针 | 每次 12-16 秒,全 False 率极高 | 探针窗口按"部署过命杯"固定触发,不按升档概率条件化 |
| ⑤刷新失效慢判 | 商店点刷新货架不变,连点 3 轮才判停 | 每例 9-14 秒+误扣刷新费风险 | ShelfStale 需要 2-3 轮签名不变才触发,刷新点击本身无生效校验 |
| ⑥识别追赶盲等 | M8 已判定到达,引擎等识别流帧追上画面 | 19-68 秒(019 给徽局最慢) | M8 用自有单帧捕获判到达,引擎用识别流 LatestAnalysis 判现状——**两层视线不同步,引擎盲等不催** |

**共同根因**:所有等待/重试都是**固定时长+固定动作**,没有"每一步先看画面身份,再决定下一步"的状态感知。这就是为什么卡住时永远卡满上限。

## 二、修复设计(七簇)

### 簇 A:状态感知弃局(消灭 117 分钟黑洞)
**位置**:`CurrencyWarsRejectedOpeningRecovery.cs`(弃局恢复)+`GrailDecisionEngine` 弃局决策点。
**设计**:
1. 弃局链每一步动作前强制 I1 验页(现有页面门禁),按页 ID 分流:
   - `wish_trial_selection`/`gala_star_bond_selection` → 调用现有泵应答(2 秒),**不按 Esc**;
   - 环境选择页(投资环境页族) → **过路必选**:选最左环境+确认进局,转局内弃局(坑 47 逻辑接入弃局链);
   - `preparation_*` → **终止弃局,返回"局仍在"事实**(上层重新评估,大概率救回命中局);
   - `normal_hud` → 弃局完成;
   - 结算中间页族 → 维持盲点直通(四.22 不变)。
2. 全链硬上限 90 秒;超时=诚实 Failed+响亮事件(不再有 23 分钟游程)。
3. 每次弃局的**发起原因必须留痕**(决策叙述进回执+RecoveryStarted 事件带 reason 字段)——消灭"无留痕弃局"。

### 簇 B:A4 点选装配收尾+自证加固(消灭出战失败 3/3 必现链)
**位置**:`PreparationFormation.Grail.cs`(A4 装配)。
**设计**:
1. 装配动作成功自证后,**主动 Esc 一次+I1 验页**(关闭点选点角色卡弹出的详情框);Esc 后页面仍非 preparation=再点空白+验页,仍失败=装配如实报 Fail(带"详情框无法关闭"原因)。
2. 自证条件从"徽离物品栏"升级为"**徽离物品栏 AND 验页干净**"双条件——堵"详情框遮挡物品栏→假离栏"假成功(局 12/13 无自证事件即此症)。
3. 出战(RewardBattleStart)3 次耗尽后的处置:不再"等待外层重试",改为 **Esc+验页→若见弹框先应答→重试一次出战→仍失败才交决策层**,全链 ≤40 秒。

### 簇 C:弹框泵全覆盖(消灭时点缺口)
**位置**:泵调用点(GrailRunLoop/GrailMacroCommands/引擎)。
**设计**:新增统一守卫 `EnsureNoBlockingModalAsync(handle, ct)`(内部=I1 验页→见 wish/gala 弹框→应答→复验,复用现有多数组件),接入四个此前无覆盖的时点:**M2 开矿前、商店每轮识别前、M1 出战前置门后、快照长尾每次重试前**。原则:不再依赖"恰好在泵覆盖点弹框"的运气。

### 簇 D:规则落地(四.13a+四.5)
**位置**:`GrailDecisionEngine`。
1. **四.13a**:M7 选定策略后立即判定:用户目标=全员三星五费 ∧ 1-2 血≤86(引擎现有读数) ∧ 选定策略 ID≠276 → **立即走簇 A 新弃局链**(决策叙述带"策略弃局:血 X/策略 Y"),选择时不延迟(局 1 的 90 秒白花消灭)。单人模式永不触发。
2. **四.5**:部署候选存在(备战席有可上单位)且前台无空位时 → 检查人口:人口<4 且金币≥8 → 买经验×2(写入决策叙述)→ 再部署。部署目标槽=**实时空槽识别**(复用 1.2.109 ReadLiveSlotOccupancyAsync),禁止吃陈旧快照选槽(局 3 八连败根因)。

### 簇 E:快照不可得≠弃局
**位置**:`GrailDecisionEngine` 判定点+`GrailRecognitionCommands`(I10)。
1. 长尾 60s 耗尽后**禁止直接弃局**:先 EnsureNoBlockingModal(簇 C)→ 触发流救援(现有通道)→ 再给 30s 窗;仍不可得 → 上报"快照持续不可得"响亮事件并继续重试(上限 5 分钟),**弃局只能由 R3 真前提**(金<刷新价 ∧ 可卖=0,从明细推演,两帧一致)触发。
2. "R3/失败"标签拆分:弃局回执必须写真实原因(山穷水尽/策略弃局/弹框不可解/快照不可得超限),禁止混用。
3. 识别追赶正面信号:快照等待循环加**提前退出**——I1 报 preparation 且帧龄<3 秒即采用(不等退避梯走完),配合现有 5s 梯。

### 簇 F:商店循环质量
1. 刷新点击后**下一轮识别即校验货架签名**:不变→立即换刷新落点重试一次(±20px),再不变才计 ShelfStale(2 轮判停不变)。
2. ShelfStale 判停=本段终局;**段间重开只允许"金回流入账≥刷新价×3"**一种理由(堵多段空转)。
3. 识别降级段(单帧快扫)只观察不购买(堵低质量识别触发误买/漏买争议)。

### 簇 G:监督整改(制度,非代码)
逐局"三问"审计(该做吗/做对了吗/失败处置对吗)+R3 前提核对+弃局原因留痕核对,写入值守口径(RE_AUDIT 已立,handoff 同步)。

## 三、四点检查单(铁律 8)

1. **不违背既有设计思想**:分层自愈(服务层双看门狗管管线,决策层管对局)不变;本方案全在决策/操作层,未动识别管线;四.22(结算页盲点直通)原样保留,簇 A 的页面分流不识别结算中间页。
2. **不改用户已拍板内容**:四.13a/四.5 正是用户拍板的落地,非更改;四.20/四.22/四.23 口径零触碰;凑息/退避梯等已实装功能不动。
3. **不违背游戏机制**:环境选择=强制模态(坑 47 已核);祈愿/盛会=模态吞 Esc(坑 50 已核);人口-经验机制(四.5 用户口径)照抄。
4. **不违背原指令集/决策树**:所有新增守卫是"等待/重试循环内的检查点",不新增指令、不改决策树节点序;M7 选策略时机与 N3-N11 逻辑不变(只在其后追加 13a 判定)。

## 五、风险与回退

- 簇 A 的"备战页终止弃局"新增"局仍在"返回路径——上层必须正确处理(重估而非再弃):实现时以枚举结果(Completed/StillInGame/Failed)强制上层分支,防 fallthrough。
- 簇 D2 买经验改资金计划:与凑息(金<10)及刷新需求的资金竞争——顺序固定为:清场→凑息→买经验(若触发条件)→圣杯循环,买经验只在"有候选可上"时执行,不影响循环资金上限。
- 全部改动集中在决策层/操作层,识别管线零改动;回退=单 commit revert。
