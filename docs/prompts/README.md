# 模块对话提示词与派发顺序

这些文件是可以直接复制到模块对话的启动提示词。它们按 2026-07-26 的实际进度编写：用户亲自测试 `artifacts/live-test-30`，发现 Bug 后直接把对应模块提示词和自然语言 Bug 描述发给该模块，不继续盲目增加功能。

## 现在应该怎么发

| 顺序 | 提示词 | 发给谁 | 负责什么 | 何时发送 |
|---|---|---|---|---|
| 0 | `BUG_REPORT_TEMPLATE.md` | 用户自己使用 | 用最少信息记录现象；不要求填全 | 每次发现 Bug 时 |
| 1A | `vision-recognition.md` | “视觉识别与捕获”对话 | 修复启动捕获、页面误识别、OCR/模板问题 | Bug 指向 Vision 时直接发送 |
| 1B | `opening-reroll.md` | “开局导航与重刷”对话 | 修复正向导航、筛选、退出结算和多轮恢复 | Bug 指向开局流程时直接发送 |
| 1C | `ui-overlay.md` | “UI 与悬浮窗”对话 | 修复界面、热键、实验标记和设置传递 | 出现 UI/热键/设置问题时直接发送 |
| 1D | `reward-stage.md` | “备战与奖励关”对话 | 修复布阵、商店、战斗、策略刷新 | 测到对应阶段并发现 Bug 时发送 |
| 2 | `project-control.md` | 总控与集成对话 | 处理无法判断归属或跨模块 Bug，维护总状态 | 不确定发给谁或模块修复完成后 |
| 阶段性 | `testing-release.md` | “测试、证据与发布”对话 | 整理用户测试证据、核对构建、做发布门禁；不操纵游戏 | 一批 Bug 修复并由用户复测后 |
| 并行但需协调 | `data-knowledge-base.md` | 新建“运行时数据接入”对话 | schema、校验器、转换层；不负责联网采集 | 上游 raw 文件稳定且确认无人同时写时发送 |

发送方式：复制对应提示词全文，在末尾直接补一句或几句 Bug 现象即可。无需先整理成专业报告；模块对话必须主动检查最新日志、截图和相关代码，只在关键信息确实缺失时再向用户提问。

## Bug 路由速查

- 应用无法启动、黑帧、WGC 异常、页面/OCR 误识别 → Vision。
- 页面顺序错误、错误点击、已有对局未停止、退出后回不去、多轮重刷卡住 → Opening/Reroll。
- 1-1 角色卡、拖动、商店、晶矿球、战斗、投资策略 → Reward Stage；若纯像素/OCR 原因，再由 Vision 协作。
- 主题、布局、设置保存、热键、悬浮窗、实验功能提示 → UI。
- JSON 字段、ID、枚举、版本、引用、导入失败 → Runtime Data Import。
- 无法判断归属、涉及多个模块、是否能发布 → Project Control。

## 并发规则

- `App.xaml.cs`、`MainViewModel.cs`、`OpeningRerollLoopCoordinator.cs`、`OpeningFilters.cs`、`RewardStageAutomation.cs`、`PROJECT_STATUS.md` 和 `data/4.4/` 都是高冲突文件。
- 不要让多个对话同时修改同一高冲突文件。
- 用户负责游戏实机测试；任何模块对话都不得自行操纵游戏、BGI 或桌面。
- 模块对话负责修复和 L1/L2/L3 验证，修复完成后交用户复测；用户反馈的实机结果才可形成 L4 证据。
- 上游“数据与攻略知识库”对话负责 raw 资料；`data-knowledge-base.md` 应发给运行时 schema/导入对话，不要混为同一职责。
