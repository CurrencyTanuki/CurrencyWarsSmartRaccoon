## ✅ 修好的 5 项

### 1. F · 结算/战斗帧不再被丢弃（滞后 20s+ 根因）
**根因**：32 张关键帧（16 battle_generic + 14 miss(Unknown) + 1 settlement）被去重/间隔丢，根本不进识别 → 结算伤害读不到、节点记录缺失、滞后 20s+。
**改动**：`Phase2RealtimeRecognitionPipeline` 去重块——`battle/battleSettlement` 帧 + `SceneTransition` 帧排除相似去重。
**自查**：帧/调度测试 37/38（唯一失败=既有基线 UnclassifiedSettlement）；全量 894/915（19 失败为既有基线）。

### 2. S1+S2 · 前台误判（阿格莱雅被误判白厄）
**根因（实测闭环）**：识别器 standard 路径 front0=阿格莱雅(0.57)；但 `DetectCallEffect`(应援检测) 把 front0 左右两侧背景蓝(亮蓝12-26%)误判成应援棒（真应援棒14-18%不可分）→ front0 走 excludeSides → Match detail 裁剪 → 阿格莱雅漂移成白厄。
**改动（方向2 强门控）**：应援检测改为【识别后】——先用标准路径识别，确认开拓者欢愉在场才对该帧被 DetectCallEffect 检出的槽用 excludeSides 重识别。无开拓者 → 纯标准路径。
**自查**：front0 083742 = 阿格莱雅(0.571)、084211 = 阿格莱雅(0.579)（原白厄/未知）。UserReference/UserReferenceFull/SilverWolf 40/40 通过。

### 3. S3 · 结算伤害数字不再被头像拖累丢弃
**根因**：伤害数字完整读入 rows(1-4=7378.6万)，但 `rows.All(CanDriveDecisions)` 头像 unknown → 整榜 PartialUnknown → 不落盘。
**改动**：`ReadSettlementDamageAsync` 解耦——`damageScaleResolved = complete && !ambiguousScale`（不看头像），数字读到+单位明确即 Known。头像 unknown 仅影响该行角色归属。
**自查**：Walter/Settlement/HistoricalEquipment/ChallengeReport 45/46（唯一失败=既有基线）。

### 4. S4 · 物品栏和平手枪(042)不再重复
**根因**：`InventoryIconSlots` 右列纵向 7 槽框选错位 → 同一图标被相邻槽各识别一次。
**改动**：v4 网格（R 列右5下5 + L 列紧贴同y + 第一排特殊 E）+ `ObserveInventory` 重写（第一排特殊从右到左遇空停 + 下面普通上下左右遇空停）。
**自查**：1-6/1-4 实测 SimpleEquipment=equipment_042 从 2 个 → 1 个 ✓；拆装扳手/冶金炉正确分类。UserReferenceEquipment/HistoricalEquipment/EquipmentStateMerge 等 32/32 通过。

### 5. S5 · 猎星人不再"无中生有"（备战席误标）
**根因**：`DetectHunterStar` 对**所有卡含备战席**无条件检测；阿格莱雅(金色系)左上角金色36.8%>30% 误判猎星人。
**改动**：`IsHunterStar: zone is not Bench && DetectHunterStar(...)`——备战席永不检测（用户规则：后台可、备战席不可）。
**自查**：1-4/1-6 备战席 bench:3 阿格莱雅 hunter=True→False ✓。
