# 0.2.798 更新说明（2026-08-03 14:40）

## 修复：备战页节点仍显示"未知节点"（0.2.797 实测 14:23 会话）

### 现象
0.2.797 实机（14:22:56 run）：14:23:03 到达备战页 1-1，但 14:23:06
仍报"进入备战节点 未知节点"——上一版的大区域 OCR 兜底没生效。

### 为什么 0.2.797 的修复没生效（关键）
0.2.797 把"备战阶段 X-X"大区域全文 OCR 兜底放在了 **ReadNodeAsync 的
最末尾**（数字 OCR 全部失败之后）。但实机路径是：
1. 数字 OCR（小区域）**读到了但读错**——把 1-3 读成 1-9，返回 Known
2. `if (direct.Status == Known) return direct;` —— **直接返回 1-9**，
   大区域兜底根本没机会执行

也就是说：**0.2.797 的兜底位置错了**——它只在"数字 OCR 完全失败"时
才兜底，但实机是"数字 OCR 读到但读错"，被提前 return 短路了。

### 本次修复
把"备战阶段 X-X"大区域全文 OCR 提到 **ReadNodeAsync 最前面**（优先）：
- 先读大区域全文（含"备战阶段"前缀），解析完整格式；
- 只有文本明确含"备战阶段/前台区域/后台区域"字样才采信
  （避免其他页面数字干扰）；
- 否则回退到原有数字 OCR 路径（小区域，行为不变）。

这样：实机备战页 1-3 → 大区域读"备战阶段 1-3" → 正确解析 1-3；
数字 OCR 的 1-9 误读被完全绕过。

### 测试
- 全量回归 647/647 通过（含节点相关 193 个测试）。
