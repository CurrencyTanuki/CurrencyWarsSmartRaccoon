## 1. 项目现在在做什么

项目当前仍以“币站开局小助手”为产品阶段名称，目标是通过 Windows 窗口捕获、模板识别、中文 OCR 和模拟输入，安全完成货币战争开局筛选；代码范围已经向后扩展到：

1. 从普通 HUD 进入货币战争；
2. 识别敌方阵营、敌人词条和三个投资环境；
3. 按用户规则保留或放弃开局，并连续重刷；
4. 命中后识别 1-1 备战席、拖动初始阵容；
5. 自动处理前两层奖励关、商店、晶矿球、自动战斗和首个投资策略；
6. 为后续攻略库、局势识别、评估和建议保留分层架构。

目前真实成熟度仍处于“开局正向导航曾实机跑通，自动重刷闭环和奖励关扩展待实机验证”的阶段。项目还不是完整局势助手，也不是已验证可长期无人值守的自动挂机工具。

| 等级 | 含义 | 可对外表述 |

| L1 | 编译通过 | 只能说“可编译” |
| L2 | 自动测试通过 | 只能说“测试通过”；模拟器或 Fake 不等于游戏实机 |

## 5. 已知 Bug 与技术债

### P0/P1 风险

1. **最新产物仍是实验候选。** `live-test-60` 已包含 59，并加入购买成交复核、九槽晶矿门禁、非战斗拒绝页三次 Esc 和设置 UI/默认值修正；这些都没有当前包实机闭环。B/C 的实机成功属于旧基线单段，不能自动证明新规则或完整奖励流。
2. **当前捕获后端曾在旧日志中启动崩溃。** `logs/unhandled-errors.log` 记录了 `WindowsGraphicsGameCapture.CreateDirect3DDevice()` 的 `InvalidCastException`。代码后来修改为多 DXGI 接口尝试，但修改后没有新的启动成功日志。根目录的 `driver-repair.ps1` 是硬件专用系统维修脚本，不属于应用运行时，也从未在本次审计中执行。
3. **未实机验证的奖励关自动化默认开启。** `MainViewModel` 默认 `EnableRewardStageAutomation=true`；自动重刷命中后会继续布阵、奖励关和投资策略选择。这扩大了首次用户操作风险。
4. **有限预算仍需实机校准。** 当前商店开关、布阵/出售、战斗监测、成功页继续、投资策略确认和退出恢复均已有明确上限、页面重识别和安全停止；但等待时间与预算只根据 test38 日志和回放设定，尚未形成当前候选的实机校准证据。
5. **页面识别大多只有一个模板锚点。** 20 个页面中只有 `guide_currency_wars` 使用两个锚点，其余页面依赖单锚点；与“双锚点/多方法确认”的安全目标不一致。

### P2 风险

6. **离线样本覆盖窄。** 25 张正向页面回放覆盖了当前页面类型，但多数页面只有单样本；没有 100/125/150% 缩放、悬停、遮挡、亮度和大量负样本的准确率报告。

## 6. 产品风险

- 产品名称和宣传仍聚焦“开局助手”，代码却默认延伸到奖励关和投资策略；用户对自动化范围可能产生误解。
- 未完成的奖励关能力默认开启，会把实验能力暴露为常规能力。
- 第三方自动化可能违反游戏服务条款或产生账号风险，发布页必须清晰提示。
- 开局规则、投资策略偏好、角色保留和商店购买设置逐渐复杂，但缺少首次运行安全向导与能力成熟度提示。
- 数据版本固定为 4.4，游戏更新后页面模板、名称和规则都可能失效；当前没有自动降级到观察模式的版本门禁。
- 项目声称源码公开且禁止商业使用，但根目录尚无正式许可证，公开发布存在法律和协作风险。

## 7. 推荐的下一步开发顺序

1. **建立可发布基线。** 恢复有效 Git 仓库；给 `live-test-30` 或后继产物记录版本号、源代码指纹、构建命令和测试结果。未验证的奖励关自动化先默认关闭，并在 UI 标注实验状态。
2. **当前产物最小实机冒烟。** 只验证启动、窗口发现、截图、观察模式和停止热键；确认 WGC 修复有效。此步骤需要用户明确授权后另做，当前审计未执行。
3. **开局主路径回归。** 用当前产物重新验证 HUD → 投资环境 → 停止，验证失焦暂停/恢复和已有对局保护；记录完整日志与截图证据。
4. **退出重刷闭环。** 单独验证“不合格 → 进入 1-1 → 退出 → 放弃结算 → 返回首页”，再做 2～5 轮循环。每个动作增加有限尝试和恢复状态，不允许无限盲点。
5. **逐类扩展数据入口。** 复用装备样板，把投资环境、策略、词条、竞争对手、角色和羁绊逐类迁移；在完成等价回归和接口影响审查前不切换`GameDataCatalog`，也不覆盖`data/4.4`。
6. **布阵模块灰度。** 先只识别和显示方案，再授权单次拖动，最后验证完整三人布阵。
7. **奖励关分段验证。** 依次验证商店开关与 OCR、1-1 出战、结算到 1-2、晶矿球、1-2 出战、投资策略识别和刷新；每段通过后才接入连续流程。
8. **扩大视觉数据集。** 建立多分辨率/缩放/动画/负样本基准和准确率报告，为每个危险页面增加第二锚点或跨方法确认。
9. **再进入高级产品能力。** 完成稳定开局和奖励关后，才开始 `RunSnapshot`、攻略检索、局势评估和建议排序。
