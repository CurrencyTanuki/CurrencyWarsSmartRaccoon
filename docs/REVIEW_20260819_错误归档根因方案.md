# 三、核心深挖：能量地块为何「只伤前台、不伤后台」→ 前台/后台代码路径差异

> 这是本次最重要的排查点。用户判断正确：同样特效，后台能识别、前台不能，**必是前/后台识别代码不同**。

### 识别路径差异（代码事实）

| | **前台(Front)** | **后台(Back)** |
|---|---|---|
| 图像源 | **原始 frame** + 固定参考坐标 `PreparationCharacterSlots1920`（识别时 Normalize 原图）| **WarpBackRow 透视校正后的 warp 帧** |
| 槽位 | 固定 2K→1920 参考坐标（`boardReferenceSlots` 前 4 格）| warp 后槽位矩形（`warpedBackSlots`）|
| options | 前台用 `boardOptions`（Standard，无内缩、0.90 惩罚线）| 后台 `boardOptions with { BackRow=true }`（内缩 6px 剔除边缘 + 0.80 宽松触发线 + 0.50/0.015 降阈值）|
| 星级带 | StarBand.FrontCenter（Normalize 后双带）| StarBand.BackRight（原始帧 + warp）|

### 根因判断
- **后台有 `BackRow=true` 内缩 6px**：会把卡面边缘（含能量地块特效带）**裁掉**后再匹配 → 特效对后台影响小 → 角色能识别（证据：后台每次识别出藿藿/千冶刃，只是装备带丢）。
- **前台没有内缩**：前台 1 号位直接拿「含能量地块特效」的原始裁剪做全卡匹配 → CCoeffNormed 结构分被特效污染拉低（0.54 <0.55）→ 判定 Uncertain。
- **后台装备漏、前台角色漏** 的差异正源于此：后台靠内缩躲过特效（但装备带区域更靠边，内缩后装备带检测区错位→装备丢）；前台没内缩所以整卡含特效→角色就认不出。

### 验证/结论
- 用户观察到"后台每次识别出（只是装备掉）、前台完全识别不出" → **与我的内缩实现吻合**：后台内缩剔了特效、前台没内缩被特效压。
- 前台 1 号位特效最重（紧邻前台左侧边界？）→ 单帧 conf 0.54 vs 阈值 0.55 临界。

# 四、逐项修复方案（待审核）

## 方案 A1（核心）：前台识别也做「能量地块特效」规避
**目标**：让前台卡面匹配避开能量地块特效（同后台内缩思路，但只针对特效带，不伤正常卡面）。
候选：
- **A1-1（推荐，最小）**：给前台槽位识别加「卡面内缩」——仅对前台槽匹配的 `searchImage` 内缩（同后台 backRow 内缩 4-6px，且**星级仍用原槽**）。前台 Slot0（及整个前台）卡面边缘特效带被裁掉 → 结构分回升。
  - 但注意：前台卡面四边含星级/边框，不能全内缩，需只缩「特效侧」（1号位右/下缘？）——待实机取 1 张「能量激活」和「能量关闭」对比，标定特效带位置。
- **A1-2（治本）**：探测「能量地块特效」区域，对该槽匹配时**局部排除特效像素**（类似 DetectHunterStar 那种区域检测），或不把特效区计入 CCoeffNormed。
- **A1-3**：参考后台成功经验——**直接让前台走与后台相同的内缩路径**，验证是否 1 号位即恢复（若前台只是没内缩这一差异，A1-1 即可）。

## 方案 A3（猎星人）：保留金黄像素检测，加「人数/羁绊」约束
- 保留 `DetectHunterStar` 金像素检测不变。
